# نطاق الترحيل

المرجع هو نسخة nav-app الحالية بكل مساراتها ومزاياها المتاحة. ابدأ بـ nav-app/src/main.ts وتهيئة التطبيق، وتتبع التبويبات والشاشات والمكوّنات والخدمات والـ feature flags. راجع كل ملفات nav-app/e2e والاختبارات بجانب المصدر وnav-app/LOVABLE-INTEGRATION.md. استخدم attackwise/docs/migration/FEATURE_INVENTORY.md وملفات audit نقطة بداية، ثم سجّل أي فرق. افحص الملفات التي تشير إليها الوثائق قبل الاعتماد عليها.

| المجال | السلوك المطلوب فحصه وحفظه |
|---|---|
| نقطة الدخول والتخطيط | الصفحة الأولى، إنشاء خطة Enterprise وفتح الخطط وتسميتها والتبديل بينها، الاستعادة والحفظ التلقائي وحالات فشل القراءة أو التخزين. ميّز بين قيود واجهة التخطيط ودعم المجالات في Navigator. |
| الاختيار والدفاع | التقنيات والتقنيات الفرعية، التكتيكات والفلاتر، اختيار الدفاع لكل تقنية، الدفاعات المخصصة والروابط اليدوية، بيانات D3FEND المحلية ومصدر العلاقة. افحص أثر إزالة عنصر على بقية الخطة. |
| الحساب والتقارير | استخرج المعادلات والدقة والتقريب من التنفيذ الفعلي. قارِن نفس المدخلات في Angular وVue، ومنها القيمة الغائبة والصفر والقيم السالبة والحدود. افحص محتوى تقرير Word والرسوم والحقول بعد التصدير. |
| الواجهة | العربية والإنجليزية، RTL وLTR، تبديل اللغة والثيم واستعادتهما، الهاتف وسطح المكتب، لوحة المفاتيح والتركيز، الأيقونات ورسائل الخطأ وإعادة المحاولة. |
| Navigator | بيانات STIX وعلاقاتها وإصداراتها، المصفوفات وتخطيطاتها، التبويبات، اختيار الخلايا، التعليقات والألوان والدرجات، البحث والمرشحات والطبقات المشتقة والمقارنات. غطِّ الإعدادات والروابط العميقة ومصادر البيانات المخصصة بحسب سلوك المرجع. |
| الملفات | ميّز بين صيغة خطة ATT&CKWISE وصيغة طبقة Navigator. اختبر الملفات القديمة والحالية والطبقات المتعددة وصادرات JSON وSVG وXLSX وDOCX بحسب مسارها. افحص الإصدارات المدعومة فعليًا والامتدادات الموثقة. |
| البيانات المحلية | اقرأ plan-storage.service.ts والخدمات المرتبطة واستخرج جميع مفاتيح التخزين وتوقيت الكتابة. تشمل أمثلة التخزين attackwise-plans وattackwise-draft. حافظ على قراءة البيانات السابقة وعلى إمكانية الرجوع للأصل. إذا احتاج الشكل الجديد تمثيلًا غير متوافق، اكتب في مفتاح جديد بعد التحقق من نجاح القراءة والتحويل، واحتفظ بالقيمة الأصلية. |

## توزيع المسؤوليات

استخدم attackwise/backend القائم وملف composer.lock. افحص routes/api.php مقابل attackwise/shared/contracts/api.md. نفّذ مسارات قراءة فهرس ATT&CK والحزم الرسمية حسب المجال والإصدار مع التخزين المؤقت ومعالجة الأخطاء. تحقّق من المصدر والمسارات المسموح بها. أبقِ البيانات الرسمية حقيقية ومحددة الإصدار. استخدم البيانات المصغّرة في الاختبارات فقط.

أنشئ Vue في attackwise/frontend. أبقِ الخطط والطبقات وملفات الاستيراد والتصدير محلية في المتصفح. لا تضف حسابات أو رفع ملفات أو وسيط URL مفتوح. خطط للتوافق مع نفس أصل الموقع عند التبديل مستقبلًا، لأن localStorage يتبع البروتوكول والمضيف والمنفذ. استخدم بيانات اصطناعية لإثبات التوافق، واذكر في تعليمات التشغيل أثر تشغيل الواجهة على منفذ مختلف.
