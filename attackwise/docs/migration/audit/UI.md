# Navigator UI source audit

Reference: the local Navigator 5.3.2 checkout, Git base `7e960e38`, including preexisting working-tree edits. Audit date: 2026-11-16. This document records source evidence, not executed acceptance tests or migrated parity. Every row below is **audited / target unverified** until the migration inventory supplies implementation and passing evidence.

## Scope and interpretation

The audit inspected component implementations, templates, matrix styles, shared styling/layout rules, `USAGE.md`, configuration, browser utilities, component test assertions, and current E2E scenarios. It traced event handlers through the view-model/services instead of treating visible controls as implementations. The domain audit owns the detailed serialization and calculation algorithms.

Paths in the tables are relative to `nav-app/src/app/`. A filename stem such as `tabs` means `tabs/tabs.component.ts` and its adjacent template; `datatable` means `datatable/data-table.component.ts` and its template. Explicit methods identify the behavior. Proposed Vue filenames describe responsibility and do not claim that those files exist. UI operations remain local; only ATT&CK/configuration reads may need the versioned Laravel API. No layer upload/persistence endpoint is required by these UI workflows.

## Local changes versus migration scope

The original working tree already contains ATT&CKWISE branding, a dark default theme, a named plan form, and Attack Plan / Defense Plan / Final Plan navigation. These appear in the uncommitted `app.component.ts`, `tabs/tabs.component.ts`, `tabs/tabs.component.html`, `tabs/tabs.component.scss`, and `e2e/plan.spec.ts`. `createPlan`, `openPlanView`, and `planWorkspaces: WeakMap<Tab, PlanWorkspace>` implement session-local groups of ordinary independent layer tabs. They are not upstream MITRE features at the recorded Git base. The existing Angular files must be preserved byte-for-byte; the explicit migration instruction excludes building these future plan features in the new application. This distinction must remain visible in the parity report.

## Styling and browser behavior

`matrix-common.scss` establishes 14 px cell units (12 px for print). Side/flat layouts retain table columns, sticky name/count headers, expansion rails and independently filtered children. Mini layout uses inline cells with outlines around parent groups. `technique-cell.component.scss` distinguishes editing, highlighted, disabled, underlined, colored and unannotated states; mini uses x/i glyphs. `cell-popover.scss` chooses four quadrants; tooltips cap height at 45vh and scroll. Sidebar width is 38em. SVG preview bounds are 75vw by 60vh. Matrix panels scroll horizontally rather than collapsing tactic columns into a mobile redesign. Legend and toolbars have dedicated print suppression.

The styling system is `src/colors.scss` adaptive light/dark mixins plus `src/styles.scss`, component SCSS, Roboto/Roboto Mono, local MaterialIcons TTF, and Angular Material theme styles. Some templates additionally load Google Material Symbols/Icons CSS. The migrated application must not accidentally lose icon glyphs, dark-mode contrast, compact spacing, or the matrix's horizontal scroll behavior when Angular Material is removed. Preserve local assets and test disconnected-network behavior; no fixed supported viewport matrix was declared in source.

Browser APIs used: `FileReader`, `Blob`, `URL.createObjectURL`, synthetic download anchors, `XMLSerializer`, clipboard selection/`execCommand`, cookies, `matchMedia`, `beforeunload`, window.open, `scrollIntoView`, timers, element bounding boxes, SVG `getBBox`, scroll listeners and native drag/drop through ngx-drag-drop. Local layer state lives in memory; the UI source does not use localStorage/sessionStorage for layers. Closing/reloading can lose local work, hence export and leave-site warning matter.

## Source discrepancies and baseline candidates

These are source-observed discrepancies or likely defects, not newly introduced migration defects. Browser reproduction belongs in baseline results.

1. `USAGE.md` states a ten-layer maximum; the current add-tab template checks `layerTabs.length < 12`. Programmatic/default imports are not gated by this UI limit.
2. USAGE describes editing a tab title directly. The current tab template has a text label and click handler; actual rename input is in layer settings. Clicking the active tab sets a `description` dropdown state, but the current DataTable template contains no corresponding description dropdown.
3. No dedicated duplicate-layer UI exists in the inspected implementation. Existing reproduction paths are property inheritance and export/re-import. Preserve those; any extra duplicate convenience control is not evidence of original-feature coverage.
4. Direct export formats found are JSON, XLSX, and SVG. No built-in PNG/JPEG exporter was found. PDF is browser print. Do not create a fake image-export requirement or report unsupported formats as migrated originals.
5. `readJSONFile` calls `versionMismatchWarning` twice, parses outer JSON outside its inner try/catch, and creates an outer Promise without success resolution. Invalid outer JSON and double warning handling need explicit baseline evidence.
6. Excel's `styleCells` and `getDisplayName` reference `this.viewModel` even while multi-layer export passes another VM to helpers. Layers with differing aggregate/label settings may expose a preexisting cross-layer formatting defect.
7. `updateStickyToolbar` adds the scroll listener in both branches; destruction removes it from `document.body` although initialization attaches it to `scrollRef`. Resource cleanup warrants a migration fix and documented behavior review.
8. `SvgExportComponent.setSize` assigns numeric preset values in inches but `toPx` interprets them using the currently selected unit; cycling units can change physical output size instead of converting values. Preserve/document intentional semantics after baseline comparison.
9. SVG `RenderableTactic` sorts parents but only filters children; UI `applyControls` sorts both. Output order comparison must account for this implementation detail rather than assuming one render path.
10. Source UI cells/context actions are clickable divs without grid keyboard handlers. The three toolbar settings handlers accept Enter/Space, but their template divs do not declare tabindex. Preserve existing supported keyboard behavior and document any accessibility correction; do not claim extensive existing grid keyboard support.
11. Search auto-expansion uses legacy numeric indices also reused by the Data Components panel, while additional categories have been inserted. Test categories and manual expansion rather than treating panel state as obviously correct.
12. Documentation describes metadata underlines as yellow; configuration defaults `metadata_color` to purple and `Cell.getTechniqueUnderlineColor` honors it. Source configuration is authoritative.
